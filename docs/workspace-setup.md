# เปิดใช้การบันทึกงานออนไลน์และ baseline

โค้ดต้องใช้ migration `supabase/migrations/005_workspace_persistence.sql` ก่อนเริ่มใช้งาน เวอร์ชันที่มีระบบบันทึกออนไลน์ deploy บน Vercel แล้ว และตรวจพบตาราง `project_workspaces` ในฐานข้อมูลจริง ขั้นตอนด้านล่างใช้สำหรับตั้งค่าระบบใหม่และตรวจการใช้งาน

1. เปิด SQL Editor ของ Supabase โปรเจกต์ที่ตั้งไว้ใน `NEXT_PUBLIC_SUPABASE_URL`
2. วางเนื้อหาทั้งหมดของ `supabase/migrations/005_workspace_persistence.sql` แล้วกด Run ไฟล์ทำงานใน transaction เดียว และรันซ้ำได้ ต้องมี migrations 001–004 อยู่แล้ว
3. เปิดโปรเจกต์ในแอปจากเบราว์เซอร์เครื่องเดิมด้วยบัญชีเจ้าของ งานเก่าใน localStorage จะย้ายขึ้นฐานข้อมูลครั้งแรก และสำเนาเดิมยังอยู่ ถ้าโปรเจกต์มีงานออนไลน์แล้ว แอปจะใช้ข้อมูลออนไลน์เป็นหลัก
4. รอข้อความ “บันทึกออนไลน์แล้ว” ก่อนปิดหน้า ลองเปิดด้วยบัญชีสมาชิกหรือเบราว์เซอร์อีกเครื่อง แล้วตรวจว่าเห็น requirements แผนผัง และประวัติเดียวกัน
5. กด Confirm baseline จากบัญชีเจ้าของ ระบบเก็บ snapshot V1 และเวลายืนยันถาวร รีเฟรชแล้วสถานะต้องยังอยู่
6. ตรวจข้อความลูกค้าหรือ PDF ใน Changes แล้วกด Apply เฉพาะเมื่อยอมรับงานนั้น การตรวจครั้งต่อไปใช้ขอบเขตที่อนุมัติล่าสุด ส่วน baseline V1 เก็บเหมือนเดิม

การแก้ map หรืออ่านบรีฟเพิ่มเติมหลังยืนยันจะเปลี่ยนงานร่าง การกด Apply คือการอนุมัติเปลี่ยนขอบเขตงาน ยังไม่ได้สร้างขั้นตอนให้ลูกค้าภายนอกเซ็นอนุมัติ

การบันทึกออนไลน์รวมแผนผัง เส้นเชื่อม requirements ประวัติ changes โน้ต เอกสาร และข้อเสนอที่ยังรอตรวจ PDF ที่อัปโหลดใหม่เก็บใน private bucket `project-briefs` และเลขเวอร์ชันเก็บในฐานข้อมูล สมาชิกที่มีสิทธิ์ดูโปรเจกต์อ่านไฟล์ได้ viewer บันทึกไม่ได้ เมื่ออีกหน้าต่างบันทึกเวอร์ชันใหม่ ระบบจะปฏิเสธการทับข้อมูล ให้ดาวน์โหลดงานสำรองก่อนโหลดข้อมูลล่าสุด

ระบบยังใช้โควตา AI ในหน่วยความจำ การย้ายโควตาไปฐานข้อมูลและการเชื่อมข้อมูลทีมจริงกับ AI เป็นงานแยกจากการแก้ข้อ 1–4 นี้

ทดสอบด้วย `npm test` และ `npm run build` การทดสอบฐานข้อมูลใช้ PostgreSQL จำลองใน PGlite ไม่แตะข้อมูล production และการทดสอบ API ใช้ AI จำลอง ไม่ใช้เครดิตจริง
