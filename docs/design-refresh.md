# TuyDui design refresh

The application uses a warm neutral workspace, dark primary actions, a small orange brand accent, and one set of global design tokens in `app/globals.css`. The second iteration removes decorative headings, repeated rounded cards, and the permanent workspace sidebar. Route styles use page-specific class names, and the production routes no longer import the previous overlapping dark stylesheets.

Updated surfaces: Google login, projects, project workspace, profile, sharing dialog, invitation, and authentication loading state.

Projects use a list with client, baseline status, access, and updated date. Search by project name, client, or description and ownership filters remain available. Horizontal workspace navigation keeps all five project sections accessible, including on mobile. The overview shows approved scope, pending decisions, assignment coverage, actual work areas with owners, and recent activity instead of a decorative map preview.

The map starts at full width. Clicking a node opens its details, while dragging and connecting nodes leave the panel closed. The details toggle opens the current selection from any section. Closing details returns keyboard focus to the toggle, and the map refits when the panel changes width. On mobile, details appear below the canvas and scroll into view. Notes, linked requirements, owner identity, and baseline confirmation remain available in the panel. Nodes retain their 220 × 132 dimensions to match connection geometry, with fit-to-screen and touch panning preserved. A native non-passive wheel listener prevents scrolling the page when zooming inside the canvas, including after changing tabs.

After the owner's first successful AI map generation in a session, an unconfirmed project opens a baseline prompt immediately. PDF import and building a map from accepted text requirements use this same flow. The owner can review first or explicitly confirm; generation and dismissal never confirm the baseline. A confirmation action stays above an unconfirmed map with requirements, including after reload. Confirmation saves pending work before locking the original baseline, and a failure stays visible in the dialog for retry. Editors see that the owner must confirm; viewers and editors do not receive the confirmation dialog. Confirmed projects no longer show either reminder. The existing immutable baseline and approved-change behavior is retained.

Native dialogs support Escape, focus containment, and return focus; manual node and requirement additions retain the existing stored fields. Login, profile, sharing, and invitations use simpler layouts consistent with the workspace.

The interface is now in English, including navigation, forms, placeholders, loading and save states, permission labels, accessible names, and locally generated error messages. The document language is `en`, and date formatting uses `en-US` with Gregorian years. Responsive navigation accommodates the longer English labels. Project names, notes, uploaded briefs, and AI output keep their source language; changing the interface language does not translate stored project content or change the AI source-language policy.

The UI uses the existing workspace and authentication handlers. API contracts, database migrations, approved-scope logic, baseline persistence, and AI requests were retained. Sharing controls now use the project's existing owner permission instead of showing owner controls to every viewer. Draft nodes display a separate status from nodes in the approved scope.

Validation uses `npm test` (8 database/API tests), `npm run build`, and isolated Playwright smoke and wheel runs against the actual application with mocked Supabase and AI responses. The browser run covers search, filters, project creation, keyboard dialogs, manual additions, dragging and connecting nodes, panel opening and closing, automatic and explicit note saves, text and PDF import, proposal acceptance, baseline confirmation, change approval, pricing decisions, sharing, retrying failed saves, profile updates, invitation acceptance, viewer controls, and sign-out. Responsive checks cover widths 1440, 1024, 768, 701, 390, and 320. The wheel run covers first map mount, remount, nodes, horizontal scrolling, zoom limits, mobile canvas, outside-canvas scrolling, and normal scrolling in other sections. Production builds are checked as well as development mode because CSS order can differ. Screenshots are saved locally in `.design-qa/`, which is excluded from Git and Vercel uploads.

Browser fixtures do not contact the production database or spend AI credits. They verify the interface and request wiring; real Google OAuth, AI quality, and end-to-end production usage still require a signed-in user session. This work does not establish willingness to pay or add billing.
